我上一次认真写博客，是在一个需要登录、需要等编辑器加载、偶尔还会吞掉草稿的后台里。后来那个服务关了，几年积累的东西跟着一起消失。这件事让我下定决心：博客的正文必须是纯文本，托管必须是一次配置、长期不动的那种。

于是就有了现在这个站点：Hugo 生成，Stack 主题，所有文章都是 Markdown 文件，构建一次得到一堆 HTML。没有数据库，没有后台，没有需要我每月登录一次的控制台。

## 为什么是静态站点

静态站点生成器这几年没什么新鲜故事，它的好处也一直没变过：

- **快**。整站就是 HTML 和图片，首次渲染不需要等接口。
- **稳**。没有运行时，就没有运行时漏洞和插件升级。
- **可迁移**。换台电脑，只要有 Hugo 和这个仓库，站点就还能构建出来。

代价当然也有：评论、搜索、访问统计这些"动态"能力，要么用第三方，要么就不要。我选了后者——搜索用构建时生成的 JSON 索引，评论暂时不做，统计干脆不看。少一个后台，就少一份需要维护的东西。

> [!NOTE]
> 静态站点不等于不能搜索。Hugo 可以在构建时把所有文章的纯文本导成一个 JSON，前端拿它做本地匹配，几十篇文章的规模完全够用，也不依赖任何服务。

## 目录结构

我尽量让仓库的顶层保持干净，一眼能看出东西在哪：

```
blog/
├─ config/_default/     # 站点与主题配置
├─ content/
│  ├─ post/             # 文章，一篇一个目录
│  └─ page/             # 关于、归档、搜索、友链
├─ assets/img/          # 头像、favicon
├─ assets/scss/         # 自定义样式，只改配色和字体
├─ scripts/             # 生成封面图的脚本
└─ themes/              # 主题（不纳入版本管理）
```

文章用 page bundle 的形式，一篇一个目录，封面图、插图就和正文放在一起。这样删掉一篇文章只需要删一个目录，不会留下孤儿图片。

## 三个关键配置

第一，让中文排版正常。Hugo 需要知道这是中日韩文本，否则字数统计和摘要截断都会出错：

```toml
defaultContentLanguage = "zh"
hasCJKLanguage         = true
locale                 = "zh-cn"
timeZone               = "Asia/Shanghai"
```

第二，把链接定死。短链接不只是好看，它意味着我以后换主题、换分类结构，旧链接依然有效：

```toml
[permalinks]
    post = "/p/:slug/"
    page = "/:slug/"
```

第三，用 `lastmod` 而不是重写文章。内容有更新时我只改 `lastmod`，正文里加一段"补充于某月"，读者能看出这篇文章在被维护，而不是被悄悄替换。

## 封面图不必是照片

我一开始到处找免费图库，后来发现真正的问题不是版权，而是**风格不统一**：九篇文章九种色调，列表页像拼贴。最后我写了个几十行的 Node 脚本，用渐变加一个几何母题批量生成封面——同一个构图，不同的色相。

| 做法 | 生成时间 | 风格一致性 | 版权风险 |
| --- | --- | --- | --- |
| 图库照片 | 每篇十分钟 | 差 | 需要逐张确认 |
| 自己拍 | 看天气 | 中 | 无 |
| 程序生成 | 一次一秒 | 好 | 无 |

脚本不依赖任何第三方库，PNG 编码是手写的，跑一次生成整站素材。

## 部署

构建命令只有一行，产物是纯静态目录，扔到任何地方都能跑：

```bash
hugo --gc --minify --baseURL "https://example.com/"
```

我现在是本地构建后同步 `public/` 目录，五分钟能搞定。等哪天觉得手动太麻烦，再让 CI 在提交时自动构建也不迟——但那是以后的事，现在这套东西已经够用了。

## 写在最后

这个博客没有阅读量，没有订阅按钮，也不打算有。它的作用更像是给自己留的一间书房：偶尔进来写点东西，把想清楚的、没想清楚的一并放好。工具越安静，写字的念头就越容易留住。
