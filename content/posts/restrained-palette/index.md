同事第一次看到我的色板文件时问了一句：「就五个？」我理解他的意思——大多数设计稿一打开，右侧色板躺十几二十个色块，看起来才像认真做过。但我这套已经用了两年，主题换过一次，组件加了七八个，一直没觉得不够用。

## 五这个数字是怎么来的

我不是先定「五个」再去配色，而是先列角色的。页面上真正需要被区分的状态其实很少：背景、正文、次要文字、可交互的东西、可交互的东西被指到时的样子。就这五种。多出来的颜色几乎都是这五种的稀释版本——浅一点的灰、深一点的绿——它们不承担新含义，只是在同一含义上讲音量。

我真正动手删过一轮。原方案里还有一个用于分隔线的浅灰，`#E4E4E0`，用了大概四个月。后来我发现卡片自带的间距已经足够做分隔，那条线只是在替留白打补丁，于是一起删了。

## 五个色值

| 色值 | 用途 | 说明 |
| --- | --- | --- |
| `#FAF9F6` | 页面背景 | 暖白，比纯白低一点点刺眼度，长文阅读明显更稳 |
| `#1C1C1A` | 正文与标题 | 不用纯黑，留给暗色模式一点下调余地 |
| `#6B6B66` | 次要信息 | 日期、标签、图注，刚好达到 4.5:1 的对比度红线 |
| `#2F6B5E` | 链接与按钮 | 唯一的彩色，只出现在可以点的地方 |
| `#DCE9E4` | 悬停与选中 | 强调色的极淡版本，用来铺底，从不用于文字 |

## 写成变量，别写进具体的组件里

```scss
:root {
    --color-bg: #FAF9F6;
    --color-ink: #1C1C1A;
    --color-muted: #6B6B66;
    --color-accent: #2F6B5E;
    --color-accent-soft: #DCE9E4;

    --radius-card: 4px;
    --font-zh: "PingFang SC", "Microsoft YaHei", system-ui, sans-serif;
}
```

把颜色写成变量的好处不是省字，而是让「加一个新色」变成一件需要解释的事。任何组件里直接出现十六进制值，我都要停下来问一句：它属于哪个角色？问过几次之后，大多数新色就自己消失了。

> [!TIP]
> 让强调色只出现在可交互元素上。按钮、链接、当前选中项，仅此三类。遵守一两个月之后，页面上任何一处绿色都会自带「这里能点」的提示，读者不用学，我也省掉了大量图标和箭头。

## 暗色模式没有新增一个色

暗色主题上线时，我最担心的就是要不要再配一套。结果只换了两个值：背景变成 `#161715`，正文变成 `#EDECE7`。强调色保持 `#2F6B5E` 没动，因为它在这两个背景上的对比度都够。

之所以能这么省，是因为前面所有组件都只引用变量。这也反过来验证了那五个角色定义得对不对——如果一个角色在两种主题下说得通，它就是个真角色；如果说不通，它多半是我硬凑出来的。

## 怎么判断一套色板够不够克制

我有个很土的检查方法：把站点所有用色处截下来数一遍，出现少于三次的颜色全部删掉。删完页面通常会好一点点，偶尔会好很多。颜色多了不叫丰富，只是说明我还没想清楚哪个更重要。真要说这套方案教会我什么，大概是——克制不是省着用颜色，是让每个颜色都有事做。
