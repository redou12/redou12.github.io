字体选择的三个笨办法

先定行高再挑字体，只用系统字体栈，最后用眼睛在真机上测一遍。

2026年7月21日星期二 阅读时长: 3 分钟
目录
  • 一、先定行高，再挑字体
  • 二、只用系统字体栈
  • 三、用眼睛在真机上测

我换过大概十几套正文字体。有一年时间，我的浏览器书签里塞满了各种字体对比页面，试得很开心，站点的正文却始终有种说不出的别扭。后来发现，问题根本不在字体上。

下面三个办法都很笨，没有一个需要审美，但它们确实把我从「换字体」这件事里救了出来。

一、先定行高，再挑字体

挑字体的时候人容易只看字形——这个「永」字好看，那个字重刚好。但读者感受到的其实是整块文字的疏密，而疏密主要由行高决定。行高不对，换什么字体都不对；行高对了，很多字体都能用。

我现在给自己定的默认值是：

  • 中文正文：行高 1.7，段落间距 1.25 个行高
  • 中英混排：行高 1.65，拉丁字母多的段落可以降到 1.6
  • 界面里的短文本：行高 1.5，超过两行就按正文处理

这套数字不是算出来的，是我把同一段文字用四组行高打印出来、逐行读完之后挑的。方法很土，但比在屏幕上来回按方向键靠谱。

二、只用系统字体栈

我曾经很认真地给站点嵌过两个字体文件，一个中文一个英文，加起来接近 4MB。移动网络下首屏那几秒的白屏，就是它们换来的。

现在我只用系统字体栈。理由很简单：这些字体已经装在我读者的设备上了，加载成本是零，而且各平台的系统字体这两年都做得不差。中文这边最省事的写法是这样：

:root {
    --font-zh: "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei",
        "Source Han Sans SC", "Noto Sans CJK SC", system-ui, sans-serif;
    --font-en: -apple-system, "Segoe UI", Roboto, "Helvetica Neue", Arial,
        sans-serif;
    --line-height-body: 1.7;
}

body {
    font-family: var(--font-zh);
    line-height: var(--line-height-body);
    font-size: 17px;
}

顺序是有讲究的，不是随便排的。PingFang SC 放在最前面，让 macOS 和 iOS 拿到最舒服的那套；Windows 会跳到 Microsoft YaHei；后面几个是 Linux 和安卓的兜底。system-ui 放在最后而不是最前，因为我发现它在某些中文环境下会优先给出拉丁字体，中文字符反而退回默认，字形会跳。

代价当然有：不同系统上看到的字体不一样。我认了这个代价，因为读者本来就是在自己的设备上、自己的浏览器里读的。

三、用眼睛在真机上测

这条最笨，也最有用。

我给自己定了一个很具体的测试流程，只在三处看：

  1. Windows 笔记本，125% 缩放，Chrome 默认字号
  2. iPhone，把屏幕亮度调到最低，在户外自然光下看一眼
  3. 项目里某个页面临时缩到 80%，看看会不会散

第一处抓的是字重和次像素渲染的差异，第二处抓的是对比度——很多灰字在显示器上没问题，到手机上就糊成一片，第三处则是防止我为了「精致」把字号越调越小。

还有一个习惯我保留至今：写完一篇文章，把整页截图，发到手机上看一遍。凡是需要放大才能看清的地方，我就重新调一次。相反，如果一个问题只在我盯着屏幕挑刺时才出现，手机上一扫而过完全看不见，那多半是我在为难自己，不动它。

这三个办法没有一条能让我一眼挑出「正确的字体」。但它们让字体这件事退到后面去了——读者该注意的是内容，排版的工作是让人不注意到排版。真要说有什么判断标准，大概是：如果读完一篇文章，你完全没想起字体这回事，那这次就选对了。
