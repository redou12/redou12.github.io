为什么我把笔记从云端搬回了本地纯文本

一次关于「笔记到底属于谁」的搬迁，以及搬迁之后我改掉的三个习惯。

2026年3月19日星期四 阅读时长: 3 分钟

我的笔记搬过一次家，从某个云端知识库搬回了本地一个装满 .md 文件的目录。搬完之后我统计了一下：过去三年我写了 1400 多条笔记，其中被我再打开过的，不到 90 条。

这不是工具的问题，是我的问题。但工具确实让这个问题变得更隐蔽——它把"收集"做得太顺手了，顺手到我以为自己在积累。

三个让我下决心的瞬间

第一个瞬间是搜索。我想找一句三年前记下的话，明明记得里面有"熵"这个字，却搜不出来——因为当时的我把它记在了一张图片里。云端笔记的全文搜索，对图片无能为力。

第二个瞬间是导出。我想把某个笔记本整体备份，导出格式是一个 .zip，解开是几百个 HTML 文件，附件散落在另一个目录，链接全是相对路径。理论上可读，实际上不可用。

第三个瞬间最简单：我在飞机上，想查一条笔记，界面转了三秒，然后告诉我"网络不可用"。

⚠️ 警告

数据在别人的服务器上，不代表数据不存在，但访问权确实不在你手里。工具下线、账号异常、跨境访问变慢，任何一环出问题，你的笔记就只是别人硬盘上的一段字节。

现在这套长什么样

规则只有三条：

  1. 所有笔记是一个目录里的 Markdown 文件，中文文件名，按 年/月 分层。
  2. 附件放在同级 assets/ 目录，用相对路径引用，图片一律写清楚来源。
  3. 同步只依赖 Git 和一块移动硬盘。没有客户端，没有订阅。

目录大概是这样：

notes/
├─ 2026/
│  ├─ 08-hugo-搭建.md
│  └─ 09-读书笔记.md
├─ assets/
│  └─ 2026-09-封面.png
└─ index.md

搬迁之后改掉的三个习惯

不记链接，记结论。 以前我看到一篇好文章，第一反应是存链接，配一句"以后细看"。现在我强迫自己当场写三行：这篇文章解决了什么问题、它的结论是什么、我打算怎么用。写不出三行，就不存。

不建目录，先写再说。 我过去的笔记结构是一棵精心设计的树，结果每次写东西都要先想"这条该放哪个分类"，想着想着就不写了。现在全部平铺，靠文件名和搜索找。文件数上了两千再考虑分治，现在远没到。

每周做一次删除。 这条最有用。每周花二十分钟，把这一周记的东西过一遍，删掉一半。留下来的才会被认真整理。我甚至给删除设了个门槛：一条笔记如果三个月内没有被任何其它笔记引用过，它大概率是噪音。

一点代价

纯文本方案不是没有缺点。手机端体验很差——我至今没有找到一个在手机上舒服编辑 Markdown 的办法，所以手机只用来记一行字的碎片，正式整理一律回到电脑上。这反而成了优点：碎片和成文被物理隔开了。

另一个代价是搜索依赖工具。我用的是命令行里的模糊搜索，配合编辑器自带的正则查找，够用但不算优雅。好在这些都建立在文件系统之上，随时可以换。

结语

搬迁之后我最大的感受是：笔记工具的选择，本质上是在选择你和信息之间的关系。如果你希望它替你思考，那就选功能最多的那个；如果你希望它只是一个放东西的地方，那纯文本目录就已经足够，而且二十年后还能打开。

我现在属于后者。
